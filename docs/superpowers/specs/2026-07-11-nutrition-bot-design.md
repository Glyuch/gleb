# Дизайн: Telegram-бот «Нутрициолог» (nutrition-bot)

Дата: 2026-07-11
Статус: на ревью у Глеба

## Цель

Персональный Telegram-бот, воспроизводящий работу нутрициологов программы TriDaily
(чат «Глеб питание», ноябрь 2025 – январь 2026): напоминания по окнам приёмов пищи,
контроль интервалов, трекинг веса/шагов/воды, обучающие материалы, разборы еды по фото
и корректировка стратегии. Ядро — детерминированная логика (Laravel Scheduler + webhook),
ИИ (Claude API) вызывается точечно.

## Контекст и материалы

- Папка `Питание` (~30 PDF): персональная схема «Глеб питание.pdf» (правило тарелки,
  4-разовое питание, запрещённые продукты, динамика веса чт/вс, замеры),
  обучающие темы (метаболизм, интервалы, завтрак, ходьба, вода, сон, молочка,
  яйца, хлеб, жиры, «как горит жир», сборник рецептов, кофеин),
  анализы крови от 16.11.2025 (пограничный ЛПНП 3.9, КА 3.0 — учитывать в советах).
- Стиль общения — из чата «Глеб питание»: реплики Насти (напоминания, короткие реакции
  с эмодзи 🙌🏼👌🏻☺️) и Марины (объяснения «почему», корректировки). Бот — один персонаж,
  совмещающий обе роли.

## Правила программы (зашиваются в логику)

- 4 приёма: завтрак (30–90 мин после подъёма), обед, полдник, ужин (за 2–3 ч до сна).
- Интервал между приёмами 3–4 ч (жёсткие границы 2,5–4,5 ч). Перекусов нет.
- Состав приёмов: завтрак = сложные углеводы (с кулак) + фрукт/овощи;
  обед = правило тарелки (углеводы 3–5 ст.л. + белок с ладонь + салат полтарелки + фрукт);
  полдник = белок + припущенные овощи/салат + вкусняшка (углеводистая);
  ужин = только белок (кроме красного мяса); при раннем ужине допустим второй
  белковый приём ~22:00 (творог/кефир).
- Приём пищи ≤ 25 минут.
- Шаги: прогрессия 7к → 15к в день (корректируется на чек-апах).
- Вода: ≥ 2 л (2,5 л в дни тренировок). Сон: отбой ≤ 23:00.
- Взвешивание: чт и вс утром натощак. Замеры (см) — старт и финиш программы.
- Запрещёнка: банан/манго/виноград/картофель/морковь/свёкла/кукуруза/тыква,
  алкоголь, консервы, мучное, молочка (кроме творога 5–9% + грч. йогурт на ужин
  и пармезана 30 г), смешение углеводов с молочкой, смузи/соки/газировка.

## Фазы

1. **Программа** — 10 недель: старт с веса и замеров, обучающие материалы по расписанию
   тем, прогрессия шагов, финальные замеры и итоговый отчёт.
2. **Поддержка** (после 10 недель): напоминания мягче (без пинга «поели?»),
   взвешивание раз в неделю (вс), материалы отключены, саммари и чек-апы остаются.

## Динамические окна приёмов

- Дефолтные окна: завтрак 07:30–08:30, обед 11:00–12:30, полдник 14:40–16:10,
  ужин 19:00–20:00.
- После фактического приёма в T следующее окно пересчитывается: [T+3ч, T+4ч],
  напоминание в T+3ч. Границы: не раньше T+2,5ч; при задержке > T+4,5ч — пинг
  «затягивать нельзя».
- Ужин дополнительно ограничен: конец окна ≤ (отбой − 2 ч). Если ужин получился
  ранним (≥ 3,5 ч до сна) — бот предлагает второй белковый приём ~за час до сна.
- Пропущен приём совсем — остаток дня пересобирается от конца пропущенного окна.
- Изменения окон видны в `/today`.

## Взаимодействия

- **Фото еды** → определить текущее окно → ИИ-разбор (что на тарелке, соответствие
  схеме приёма, запрещёнка, короткий ответ в стиле Насти) → записать приём.
  Фото вне всякого окна → мягкое «перекусов нет 👌🏻» (логика).
- **Свободный текст** → ИИ-ответ от лица нутрициолога (база правил + профиль +
  последние 30 сообщений + данные последних дней).
- **Число после запроса** (вес/шаги/вода) → парсится логикой без ИИ.
- **Команды**:
  - `/today` — план дня, актуальные окна, что уже съедено;
  - `/stats` — вес (динамика), шаги/вода за неделю, стрики;
  - `/checkup` — чек-ап по запросу: ИИ-разбор текущего статуса недели
    (то же, что воскресный, но в любой момент);
  - `/weight 82.3`, `/steps 11200`, `/water 2.5` — ручной ввод;
  - `/skip` — сознательно пропустить приём (пересчёт окон);
  - `/settings` — показать текущие настройки (подъём/отбой/окна/цель шагов);
  - `/start`, `/help`.

## ИИ-вызовы (Claude API)

| Вызов | Модель | Триггер | Вход |
|---|---|---|---|
| Разбор фото еды | Haiku | фото | фото + тип приёма + правила состава + запрещёнка |
| Скрин шагомера/весов | Haiku | фото после запроса метрик | фото |
| Ответ на вопрос | Sonnet | свободный текст | база правил + профиль + контекст 30 сообщений |
| Саммари дня | Sonnet | 22:30 | лог дня (приёмы, интервалы, метрики, нарушения) |
| Чек-ап (вс + /checkup) | Sonnet | крон вс / команда | данные недели, динамика веса, прошлые корректировки |

- Чек-ап может выдать корректировки (порции ±%, цель шагов, сдвиг окон) —
  бот применяет их к настройкам после подтверждения Глеба кнопкой.
- Фолбэк: Claude недоступен → приём/метрика фиксируются логикой, ответ шаблоном
  («Записал 👌🏻 разбор пришлю позже»), ретрай через очередь.

## База знаний

Один раз при разработке: PDF → компактные markdown-файлы в репо
(`app/Nutrition/knowledge/`): схема питания, правило тарелки, запрещёнка,
интервалы, аль-денте, вкусняшки, выжимки тем, профиль Глеба (анализы, цели),
образцы стиля (реплики из чата). Промпты собираются из этих файлов.
Сами PDF лежат на сервере (`storage/app/nutrition/materials/`) и отправляются
в чат по расписанию тем.

## Данные (MySQL, префикс nutrition_)

- `nutrition_settings` — key/value или одна строка: wake/sleep, дефолтные окна,
  цель шагов, фаза, дата старта программы, chat_id, поправка порций.
- `nutrition_meals` — date, type, window_start/end (расчётные), eaten_at,
  photo_file_id, ai_feedback, status (eaten/skipped/missed).
- `nutrition_metrics` — date, type (weight/steps/water), value.
- `nutrition_measurements` — замеры (грудь/талия/живот/бёдра/…), moment (start/finish).
- `nutrition_messages` — направление, текст/тип, telegram_message_id, created_at
  (контекст для ИИ и отладка).
- `nutrition_topics` — тема, файл, порядок, scheduled_date, sent_at.

## Техника

- Webhook `POST /api/nutrition-bot/webhook` + `secret_token` Telegram; ответ 200 сразу,
  обработка апдейта — queued job (существующая очередь на сервере).
- Laravel Scheduler (существующий крон): поминутный тик `nutrition:tick`, который
  сравнивает текущее время с расчётным расписанием дня и шлёт то, что пора
  (идемпотентно — «что отправлено» фиксируется в БД).
- Telegram Bot API — через Http-фасад Laravel (без тяжёлых SDK).
- Anthropic API — через Http-фасад, модели в конфиге.
- `.env`: `NUTRITION_BOT_TOKEN`, `ANTHROPIC_API_KEY`, `NUTRITION_CHAT_ID`.
  Токен бота в git не попадает.
- Доступ: бот отвечает только whitelisted telegram user id (Глеб). Остальным —
  «это персональный бот».
- Кэш конфига/роутов на проде — после деплоя `php artisan config:cache route:cache`
  (существующий workflow).

## Ошибки и надёжность

- Все исходящие сообщения через один сервис с логированием в `nutrition_messages`.
- ИИ-вызовы: таймаут 60 с, 2 ретрая, фолбэк-шаблоны.
- Тик идемпотентен: перезапуск крона не дублирует напоминания.
- Webhook всегда 200 (ошибки — в лог), чтобы Telegram не копил очередь.

## Тестирование

На проде нет dev-зависимостей (pest и пр.), поэтому:
- artisan-команда `nutrition:simulate {date} {time}` — прогон тика на заданное
  время без реальной отправки (dry-run, вывод в консоль);
- ручная проверка сквозных сценариев в Telegram (фото, вопрос, вес, /checkup);
- логика расчёта окон — чистый PHP-класс, проверяется симулятором на краевых
  случаях (поздний завтрак, пропуск обеда, ранний ужин).

## Не входит (YAGNI)

- Apple Health / автоимпорт шагов (возможная фаза 3).
- Мультипользовательность (жена — отдельным решением, если понадобится).
- Подсчёт калорий/КБЖУ — программа работает порциями, не калориями.
- Голосовые сообщения, платежи, группа вместо личного чата.
