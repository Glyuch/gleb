# Штаб v1.1 — задачи территорий + ИИ-разбор

**Дата:** 2026-08-08
**Статус:** дизайн утверждён Глебом
**База:** дополняет `docs/specs/2026-08-08-shtab-management-cockpit-design.md` (v1 в проде)

## 1. Задачи территорий

Осознанное расширение против v1-принципа «не таск-трекер»: не полноценный трекер, а лёгкие чек-листы текущих задач территории. Цель — дать ИИ-разбору место, куда раскладывать «конкретные задания», и показать на карте, что прямо сейчас делается.

### Модель

```
shtab_tasks
  id, object_id → shtab_objects (cascadeOnDelete),
  title (string), is_done (bool, default false), done_at (nullable timestamp),
  assignee_person_id (nullable → shtab_people, nullOnDelete),
  is_key (bool, default false), sort, timestamps
```

- ⭐ `is_key` — «самая важная задача территории», максимум одна активная на территорию (при установке новой предыдущая снимается автоматически, без ошибки).
- Хроника: события `task_done` (payload: title, object) и `task_assigned` (payload: title; person). Создание/редактирование НЕ логируем — иначе шум. Фильтр «задачи» в Хронике.

### UI

- **Сектор на карте:** под описанием — ключевая задача (⭐ + текст + мини-аватар исполнителя, если есть) и счётчик «задачи N/M» (не сделано/всего). Клик по счётчику или ключевой задаче — диалог задач территории.
- **Диалог задач:** чек-лист — чекбокс, текст, аватар исполнителя (клик — пикер персонажа/снять), ⭐-переключатель; строка добавления сверху; закрытые задачи серым внизу, скрыты за «показать закрытые (K)».
- **Таб «Люди»:** на карточке персонажа — его незакрытые ключевые задачи (⭐ + территория + текст).

### API

`POST /shtab/tasks` {object_id, title, assignee_person_id?, is_key?}; `PATCH /shtab/tasks/{task}` {title?, is_done?, assignee_person_id?, is_key?}; `DELETE /shtab/tasks/{task}`. Board отдаёт задачи в составе объектов. Все мутации — транзакционно с событиями (done/assigned).

## 2. ИИ-разбор («Рассказать штабу»)

### Принципы (зафиксированы Глебом)

1. **ИИ только предлагает — применяет Глеб.** Каждая операция в превью с галочкой; «Применить» исполняет выбранное. Хроника остаётся историей решений Глеба.
2. **Честность о недоразобранном.** Всё, что модель не смогла превратить в операции, возвращается блоком «не смог разнести» с причиной («нет сущности для…», «неоднозначно…»). Эти остатки сохраняются — из них копится бэклог доработок штаба.

### Поток

1. Кнопка «Рассказать штабу» в шапке → модалка с textarea (свободный текст: «Вика уходит с Обмена на KYC, маржа просела, у Димы завал по запуску…»).
2. `POST /shtab/ai/digest` {text} → сервер собирает контекст (полный board + активные задачи) → Anthropic API (модель `claude-opus-5`, structured output через forced tool-use, по паттерну существующего `app/Support/Nutrition/Claude.php` — raw HTTP без новых зависимостей) → ответ: `operations[]` + `unparsed[]`.
3. Типы операций (закрытое множество v1.1): `assign` (person→object, role), `end_assignment`, `move_assignment`, `metric_status`, `focus_level`, `update_description` (дополнить описание территории), `task_add`, `task_done`, `task_assign`, `task_key`. Каждая — с человекочитаемой формулировкой для превью.
4. Превью-чеклист: операции с галочками (по умолчанию все включены), снизу — блок «Не разнесено» (текст + причина). Кнопка «Применить выбранное».
5. `POST /shtab/ai/apply` {operations: [...выбранные]} → сервер исполняет их той же бизнес-логикой, что и ручные эндпоинты (те же гарды, те же события), в одной транзакции; каждое событие получает комментарий-префикс «ИИ-разбор: …» + исходная формулировка. Событие `ai_digest` в Хронику: payload {applied_count, skipped_count, unparsed[]} + исходный текст Глеба в comment.
6. Ошибки применения отдельных операций (например, гард дубля) не валят пачку: операция помечается «не применено: причина» в ответе и попадает в unparsed-лог.

### Технически

- Клиент Anthropic — по образцу существующего в репе (Nutrition), ключ `ANTHROPIC_API_KEY` уже в окружении сервера.
- Модель отвечает через forced tool-use со строгой JSON-схемой операций — без парсинга свободного текста.
- Таймаут/ошибка API — честный тост «ИИ недоступен», ничего не применяется.
- В тестах Anthropic-клиент мокается (как у Nutrition); один живой смоук руками.

## Не входит в v1.1

Дедлайны/приоритеты задач кроме ⭐, автоприменение без подтверждения, диалоговый режим с ИИ (уточняющие вопросы), голос, автодайджесты по расписанию, история ИИ-сессий отдельным экраном (только события в Хронике).

## Критерий успеха

Глеб раз в несколько дней вываливает поток сознания в «Рассказать штабу», применяет 80%+ операций без правки, а карта и задачи остаются актуальными без ручного гемора.
