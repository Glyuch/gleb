# Дизайн v2: Мультипользовательский нутрициолог-бот + рейтинги + статистика + админка

Дата: 2026-07-12. Статус: на ревью у Глеба.
База: работающий однопользовательский бот (спека 2026-07-11), задачи 1–14 в проде.

## Цели
1. Несколько пользователей (брат, друг) с изолированными данными и персональными ИИ-профилями.
2. Онбординг нового пользователя в боте (инвайт-код → анкета ~6 вопросов → персональный профиль → старт программы).
3. Рейтинг каждого приёма в БД (балл 1–10 + разбивка) — топливо для статистики и чек-апов.
4. Веб-страница статистики per-user (подписанная ссылка из бота, без регистрации) + админка для Глеба.
5. Убрать «заточенность под Глеба»: его анализы/липиды становятся ЕГО персональным профилем, а не глобальным знанием.

## Модель данных (изменения)
- **nutrition_profiles** (новая): telegram_user_id unique, name, username, main_chat_id nullable, is_admin bool, status (onboarding|active|paused), phase, program_started_on, ai_profile text (сжатый ИИ-профиль из онбординга), settings json (wake/sleep/default_windows/steps_target/portion_adjustment), awaiting json (awaiting_setting/meal_time/meal_photo/onboarding_step — ВСЕ ожидания переезжают сюда из глобальных Settings), last_seen_at.
- **nutrition_invites** (новая): code unique, created_by_profile_id, used_by_profile_id nullable, used_at nullable.
- **profile_id** добавляется в: nutrition_meals (unique [profile_id,date,type]), nutrition_metrics (unique [profile_id,date,type]), nutrition_messages.
- **nutrition_topic_sends** (новая): profile_id, topic_id, scheduled_on, sent_at — расписание тем становится per-user; nutrition_topics остаётся чистым контентом (title/file_path/intro/position).
- **Рейтинг в nutrition_meals**: score tinyint nullable (1–10), rating json nullable: {composition_ok, forbidden:[...], interval_ok, window_ok, comment}.
- sent_events: ключи получают префикс профиля `p{profile_id}:{d}:{event}`.
- **Бэкфилл-миграция**: создать профиль Глеба (telegram_user_id из env, is_admin=true, ai_profile = содержимое нынешнего 04-profile.md, settings/phase/program_started_on из nutrition_settings), привязать к нему все существующие строки; 04-profile.md удалить из общей базы знаний (01–03 остаются общими).

## Доступ и онбординг
- Неизвестный пользователь: в личке — «Это персональный бот. Есть инвайт-код? Пришли его»; в группе — молчание. Валидный код → создаётся профиль (status=onboarding) → анкета.
- Анкета (состояние в awaiting.onboarding_step, по одному вопросу): 1) имя+цель; 2) вес/рост/возраст; 3) подъём/отбой; 4) спорт/активность; 5) ограничения в еде (аллергии, не ест); 6) заметки о здоровье (опционально, «пропустить»). После — Claude сжимает ответы в ai_profile (+дефолтные окна от подъёма/отбоя), бот показывает резюме и кнопку «🚀 Начать программу».
- /invite (только is_admin): генерит код, показывает его.
- new_chat_members: если добавивший имеет профиль → «Сделать этот чат основным для напоминаний? [Да/Нет]» → main_chat_id.
- Авторизация обработки: сообщение маршрутизируется в контекст профиля отправителя (в любом чате). Групповое сообщение не-участника — молчание.

## ИИ per-profile
- PromptBuilder::system($profile) = персона + общие знания (01-program, 02-forbidden, 03-style) + «Профиль клиента: {ai_profile}».
- dayContext($profile, $date) — только данные этого профиля.
- Vision/текст-разбор еды возвращает СТРОГИЙ JSON: {feedback, score (1–10), rating:{composition_ok bool, forbidden string[], comment}}; interval_ok/window_ok досчитывает детерминированный код (по eaten_at vs окно и прошлый приём). Балл и разбивка пишутся в meal. Кнопка «Поел» без фото/текста — score null.
- Саммари дня и чек-апы включают средний балл и топ-нарушения.

## Тик
Цикл по active-профилям; всё как сейчас, но per-profile: guard пустого main_chat_id (профиль пропускается), фаза, окна, слот-напоминания (ключи с p{id}), темы из nutrition_topic_sends, вес чт/вс, метрики, саммари, чек-ап вс.

## Веб
- **/nutrition/s/{profile}?signature=...** — подписанная (Laravel signed URL, бессрочная) страница статистики: график веса, средний балл приёмов по дням, стрики соблюдения, шаги vs цель, вода, таблица последних приёмов (тип, время, балл, нарушения). Inertia+React как остальной сайт. Команда /stats в боте шлёт краткий текст + эту ссылку.
- **/admin/nutrition** (существующий admin-middleware): список профилей (имя, статус, фаза, день программы, последняя активность, средний балл 7д), клик → та же страница статистики + управление: сгенерить инвайт, пауза/возобновление профиля, правка настроек (окна/цели), просмотр ai_profile.

## Совместимость и миграция
- Глеб продолжает работать без перерыва: бэкфилл привязывает всё к его профилю, поведение бота для него не меняется (кроме исчезновения глобальных ожиданий — они переезжают в его профиль).
- Старые sent_events без префикса не мигрируются (истекают естественно — они дневные).
- NUTRITION_USER_ID/CHAT_ID остаются как bootstrap/админ-фолбэк, но авторитет — nutrition_profiles.

## Вне скоупа v2 (YAGNI)
Лимиты токенов per-user, платежи, мультиязычность, Apple Health, редактирование общих знаний из админки, пуш «>4,5 ч» (остаётся в бэклоге).

## Риски
- Сквозная перестройка контекстов ожиданий (awaiting_*) — самая тонкая часть; переезд из глобальных Settings в profile.awaiting обязан сохранить все guard'ы (staleness, already-eaten).
- Тик по N профилям с ИИ-вызовами (саммари) — следить за временем тика; саммари/чек-апы можно слать последовательно, N мал (<10).
